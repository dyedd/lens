# 监控、隐私与排错

日常排障遵循三步路径：**概览（发现异常时段） → 请求日志（定位单次尝试链与正文） → 健康状态（查看或重置冷却）**。

## 概览面板

![概览中的请求量、成功率、Token、缓存命中率和趋势](/images/overview.png)

1. 在右上角选择统计时间范围（支持切换时区）。
2. 查看请求总量、成功率、预计费用、Token 分布与缓存命中率。
3. 切换趋势图表指标（请求数、Token、成本或总耗时）并结合活动热力图观察峰值。
4. 在下方归因卡片中按 **模型**、**渠道** 或 **Agent（客户端 User-Agent）** 下钻定位主要消耗来源。

> [!NOTE]
> 费用由模型价格表、Token/张数用量及凭证倍率估算得出。若发现费用为 0 或与上游账单存在差异，请检查 **价格** 页与对应 Key 的倍率设置；Lens 估算不替代服务商最终账单。

## 请求日志与尝试链排查

![请求日志中的模型、协议、耗时和用量](/images/request-logs.png)

打开 **请求日志**，可按时间、生命周期状态、模型组、渠道、协议或关键字筛选：

| 状态 | 含义与排查要点 |
| --- | --- |
| `连接中` | 已接收请求，正在路由或等待上游首响应（异常中断时重启会自动收敛为失败） |
| `流式中` | 已开始向客户端输出流式数据；详情页底部支持手动点击 **取消请求** |
| `成功` | 请求完整结束并记录用量与成本 |
| `失败` | 所有尝试均未成功，或流在中途报错 |
| `已取消` | 客户端主动断开或管理员在界面取消了进行中的请求（记录为 `499`） |

![失败请求详情中的上游尝试、状态码和错误](/images/request-detail.png)

### 理解“一次请求、多次尝试”

当主渠道失败并由备用渠道成功接管时：
- **列表状态**：整条请求显示为 **成功**，最终渠道显示为实际接管的渠道，但总耗时包含此前失败尝试的等待时间；
- **请求模型 vs 执行组**：若客户端使用别名（如 `daily-chat`），详情页会同时列出请求的模型组（含推理强度标记）与实际执行组及上游模型名；
- **查看尝试列表**：当前详情页在请求最终失败时直接展开 **尝试（Attempts）** 标签页；若要审计某次成功请求内部的故障转移轨迹，可使用管理员 Token 调用 `GET /api/admin/request-logs/{log_id}` 读取 `attempts` 数组。

> [!WARNING]
> **流式请求遇到 HTTP 200 后报错**：一旦首个数据块已发送给客户端，HTTP 状态码 `200` 无法再改为 `502`/`504`，Lens 也无法撤回已输出文本去更换上游重放。此时 Lens 会在协议流上发送错误事件（如 `event: error`）并终止流，同时将日志终态记为 `失败`。

### 记录正文与复制 cURL

在 **设置 → 网关** 开启 **记录请求与响应正文（`relay_log_body_enabled`）** 后，新请求的详情页会出现 **请求与响应体** 标签页，并支持一键 **复制 cURL** 复现请求。

- 开启前已经落库的请求不包含正文，无法追溯补录；
- 若同时启用了 **规则隐私**，记录的正文已经过脱敏占位符替换，复制出的 cURL 需要自行填回真实业务值。

## 规则隐私（脱敏与拦截）

在 **设置 → 隐私** 可启用本地规则引擎，在请求离开 Lens 发往上游前扫描正文中可能包含的敏感信息（不调用外部模型、不下载模型权重）：

- **检测范围**：自动扫描 `secrets`（常见 API Key、私钥、JWT、带密码连接串及中英文密码/令牌赋值）、`personal`（邮箱、手机号、校验有效的中国身份证号、通过 Luhn 校验的银行卡号）、自定义精确词（`words`）与自定义正则（`regex_rules`），并支持配置豁免词（`exceptions`）。
- **三种动作**：
  - `mask`（替换）：将敏感值替换为确定性占位符发往上游，并在收到非流式或流式响应后在内存中还原为原值返回给客户端；同时脱敏请求日志；
  - `warn`（告警）：原样发往上游，但记录隐私命中摘要并脱敏请求日志；
  - `block`（阻止）：直接在本地拒绝请求并返回隐私错误，**不计入渠道冷却或健康惩罚**。
- **会话隔离与预览**：客户端可通过 `x-lens-session-id` 请求头按会话隔离占位符映射。配置规则时，可在界面测试或调用 `POST /api/admin/settings/privacy/preview` 进行本地试运行。

完整的隐私字段限制与历史缓存边界见 [配置参考 · 规则隐私](../reference/configuration#规则隐私)。

## 健康状态与冷却管理

![健康状态中的成功率、时间线、剩余冷却与重置操作](/images/model-health.png)

在 **健康状态** 页面可按 **模型组** 或 **渠道** 两种视角查看统计：

- **成功率**：反映所选时间窗口（1h / 6h / 24h）内的历史请求结果；
- **剩余冷却**：反映内存中当前路由器的实时熔断状态，显示关联目标中最长的剩余冷却时间（例如某渠道下 A-Key 冷却 120 秒、B-Key 仍正常时，该行会提示 120 秒，但流量仍可由 B-Key 正常承接）。

**处置流程**：
1. 根据剩余冷却时长与最近失败记录，判断是短暂限流（429）还是凭证/站点故障（401/403/5xx）。
2. 在请求日志详情中定位具体失败 Key 或模型，修正凭证、余额或代理配置。
3. 点击该行操作栏的 **重置冷却**，立即解除当前进程内的冷却等待并恢复探测。重置冷却只影响实时路由状态，不会清除历史成功率统计。

## 常见故障排查速查

| 现象 | 排查顺序 |
| --- | --- |
| 返回 `401` 且请求日志里没有任何记录 | 入口认证失败发生在日志创建之前：检查使用的是否为网关密钥、密钥是否被禁用、是否过期或达到美元上限 |
| 尝试链里出现上游 `401` / `403` | 检查对应渠道的那把上游 Key 是否有效、是否限制了适用地址、账号是否欠费 |
| 请求返回 `400 invalid_model` | 检查模型名末尾是否误带了不支持的括号后缀（括号仅用于受支持的推理强度/预算） |
| 频繁触发 `429` 后切换渠道 | 查看单 Key 冷却与多 Key 限流升级阈值；若全部成员同时限流，检查上游账户并发配额 |
| 返回 `503` 且响应头含 `Retry-After` | 表示当前组所有可用目标均处于冷却中；可检查 `failover_cooled_wait_seconds` 或手动重置冷却 |
| 首 Token 耗时极长或 `504` | 检查代理连通性、目标站点延迟探测，以及 `first_token_timeout_seconds` 共享超时预算 |
| 流式输出到一半断开 | 查看 `stream_idle_timeout_seconds`、上游错误事件以及客户端是否提前取消连接 |
| 单条请求费用统计异常 | 检查 **价格** 页对应模型组的单价（含手动覆盖与图像按张计费）以及渠道凭证的消费倍率 |
