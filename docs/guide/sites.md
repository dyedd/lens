# 接入站点与模型

在 Lens 中，左侧导航的 **渠道** 页面对应底层的一个上游站点（`Site`）。一条渠道集中维护某个服务商的多个接入地址、多把 API Key、模型目录、代理方式以及请求覆盖规则。

> [!NOTE]
> 本文示例模型名使用 `gpt-6.1-sol`、`gpt-6-luna` 与 `claude-opus-5-5`，操作时请以服务商实际返回的模型目录为准。界面截图使用本地演示环境与虚构凭证。

## 理解渠道的四个核心要素

在填写表单前，先理清一条渠道内部的层次关系，避免多地址或多 Key 配置混乱：

| 要素 | 作用与特点 |
| --- | --- |
| **站点（Site）** | 顶层容器：保存渠道名称、启停状态、筛选标签（Tags）、代理模式、全局/渠道级 Header 与参数覆盖规则 |
| **接口地址（Base URL）** | 只需填写根地址（如 `https://api.openai.com`），无需拼接 `/v1/chat/completions`。可添加多个地址并指定 **地址用途**（默认、指定协议、或仅用于 `模型列表` 拉取） |
| **API 凭证（Credential）** | 一条渠道可添加多把 Key；每把 Key 可绑定 **适用地址**（未限制时默认适用于全部地址），并可配置 **倍率同步来源**（Sub2API / NewAPI） |
| **协议与模型（Protocol & Model）** | 每个地址可勾选承载的协议；每条模型记录绑定到“地址配置 + Key + 上游协议 + 模型名”，不同 Key 下的同名模型彼此独立统计与冷却 |

> [!TIP]
> **地址用途 `模型列表` 的典型用法**：部分聚合站点或反代把 `/v1/models` 单独放在管理入口域名，而推理流量走另一个网关域名。此时可新增一个用途为 **模型列表** 的地址；该地址仅用于拉取模型目录，**不会**参与推理请求调度。

| 常见上游类型 | Base URL 填写示例 | 说明 |
| --- | --- | --- |
| OpenAI / 兼容服务 | `https://api.openai.com` 或 `https://api.example.com` | 兼容服务若本身带有 `/api/paas/v4`（如 GLM）等版本化路径，直接填写完整前缀即可 |
| Anthropic | `https://api.anthropic.com` | 网关自动拼接 `/v1/messages` 并注入 `x-api-key` 与 `anthropic-version` |
| Gemini | `https://generativelanguage.googleapis.com` | 网关自动拼接 `/v1beta/models/...` 并使用 `x-goog-api-key` |
| Rerank（Cohere v2 等） | `https://api.example.com` 或 `https://api.cohere.com/v2` | 若地址以 `/v2` 结尾，Lens 自动复用该前缀拼接 `/rerank` |

## 新建与配置渠道

1. 打开 **渠道**，点击 **新建渠道**（如需批量导入多个站点，也可使用 **批量导入** 传入 JSON）。
2. 填写 **渠道名称**、**标签**（用于列表分组筛选）及主 **Base URL**。
3. 在 **API 密钥** 区域添加至少一把 Key 并填写便于区分的 **凭证名称**；如果该渠道同时有多个地址且不同 Key 权限不同，可勾选每把 Key 适用的地址。
4. 点击地址旁的 **连通性探测（Probe）** 按钮，可测试 Lens 到该地址的网络延迟与 HTTP 响应状态（先发 `HEAD`，不支持时自动回退 `GET`）。
5. 展开 **高级设置** 按需配置：
   - **支持获取模型列表**：默认开启。若上游不提供 `/models` 接口，关闭此开关，后续通过 **模型规则** 手动录入模型名。
   - **代理设置**：选择 **继承全局**、**直连** 或 **自定义代理**（如 `http://127.0.0.1:7890` 或 `socks5://...`）。
   - **凭证倍率同步**：若上游为 **Sub2API** 或 **NewAPI**，可为对应 Key 选择倍率来源（NewAPI 需指定分组名），Lens 会按计划任务或手动触发同步实际消费倍率。
   - **请求头规则（Headers）与参数覆盖（Param Override）**：支持按路径、模型、协议正则匹配追加/覆盖/移除请求头（认证头除外），以及使用点分路径（如 `temperature`、`thinking.budget_tokens`）覆盖或删除请求体参数。
6. 点击 **创建 / 保存**。

## 获取与管理模型

保存渠道后，若开启了 **支持获取模型列表**，可直接进入模型管理流程；已有渠道可在行末点击 **操作 → 管理模型**。

### 从上游目录选择

1. 点击 **获取模型列表**，Lens 会向可用地址发起目录请求（自动处理 OpenAI `has_more`/`last_id`、Anthropic `after_id` 与 Gemini `nextPageToken` 分页，单次最多 100 页）。
2. 在弹窗中勾选需要接入的模型。弹窗按模型名称聚合来源：
   - 勾选名称会加入它展示的可用地址与凭证组合；
   - 显示 **部分接入** 表示同名模型还有其他地址或 Key 尚未勾选。
3. 确认后返回渠道模型列表，逐项检查：
   - **上游协议**：Lens 会结合端点用途、上游返回字段（如 `supported_endpoint_types`）与模型名家族自动预选默认协议（如 `gpt-*` 预选 Responses、`claude-*`/`deepseek*` 预选 Anthropic 或 Chat、`gemini*` 预选 Gemini）。如果某中转站实际用 OpenAI Chat 接口提供 Claude 模型，请手动改回 **OpenAI Chat**。也可点击 **检测协议** 自动探测。
   - **上下文窗口**：可填写手动值，或点击 **检测上下文** 从已同步的 LiteLLM 元数据补全。单个模型的手动上下文优先级最高。
   - **启停状态**：停用单个模型只会禁止路由它，不会从列表中删除。
4. 点击 **保存** 使变更落盘并触发自动归组。

### 批量添加与模型规则

点击模型列表中的 **模型规则**，选择目标 Key 后，按行填写模型名或正则表达式（不区分大小写，可混合使用）：

| 规则写法 | 匹配逻辑 | 适用场景 |
| --- | --- | --- |
| `*` | 匹配上游目录返回的全部模型 | 快速全量接入单渠道 |
| `gpt-6.1-sol` | **精确字面量**：无需上游目录返回，直接加入列表 | 上游未开放 `/models` 或隐藏模型 |
| `^gpt-.*$` | **正则完整匹配**：从上游目录中筛选以 `gpt-` 开头的所有模型 | 批量接入某一系列模型 |
| `^(gpt-6\.1-sol\|gpt-6-luna)$` | **正则精确集合**：匹配这两个完整名称 | 精确筛选多款指定模型 |

> [!IMPORTANT]
> 渠道内的 **模型规则** 仅在点击 **应用到列表** 时执行一次，用于向当前 Key 的列表追加具体模型；保存后再次打开规则输入框为空。它与 [模型组匹配范围](./model-groups#设置匹配范围) 的“名称包含匹配 + 持续归组”机制不同。

### 自动与手动同步行为

在 **设置 → 计划任务 → 渠道模型同步** 中（或在 **渠道** 页手动触发同步），Lens 会按“地址 + Key”逐一核对已保存的模型：

| 核对情况 | 处理结果 |
| --- | --- |
| 原已接入的模型从上游目录下线 | 从该 Key 的模型列表移除，并同步清理对应模型组成员 |
| 原已接入的模型仍在上游目录中 | 保留已设置的启停、上游协议和手动上下文，仅刷新上游报告的上下文长度 |
| 该目标目录拉取失败或分页中断 | **保留原有全部模型**，不会因为部分页失败而误删模型；其他正常目标继续同步 |
| 该 Key 下当前模型列表为空 | 跳过本次目录拉取 |
| 渠道关闭 **支持获取模型列表** | 跳过目录获取与自动同步，完整保留当前手动模型 |

同步结果可在 **模型组 → 同步记录** 中查看每个目标的增删、归组、待分配与失败原因。

## 模型测试与兼容性验证

在渠道模型列表或模型组中点击 **测试模型**（或对整个组执行 **批量测试**），可在发往正式客户端前验证端到端连通性（测试会真实调用上游，可能产生费用）：

| 测试模式 | 行为说明 |
| --- | --- |
| **常规（Normal）** | 按当前参数覆盖规则发送流式测试请求，提取首字与输出内容 |
| **直连（Direct）** | 发送非流式最小请求，直接验证基础请求与响应解析 |
| **Codex 模拟** | 仅支持 OpenAI Chat / Responses：附带 `codex_cli_rs` 请求头与 `store: false`，专门排查 Codex 兼容性 |
| **Claude Code 模拟** | 仅支持 Anthropic：附带 `claude-cli` 请求头、系统提示词与会话 `metadata`，排查中转站对 Claude Code 特征校验 |

测试结果窗格提供请求与响应的 Debug 详情（Path、Header 与 Body），便于快速定位上游报错。

## 渠道批导入与跨平台迁移

- **同格式批量导入**：在 **渠道** 页面点击 **批量导入**，粘贴符合 `sites` 结构的 JSON（弹窗内提供标准模板），支持同批次校验与重名跳过。
- **从其他网关一键迁移**：在 **设置 → 备份与迁移 → 导入其他平台的渠道** 上传外部备份文件，支持自动识别 **Metapi**、**Sub2API**、**ccLoad (CSV)**、**All API Hub**、**Octopus** 与 **CLIProxyAPI (YAML)**，预览站点、Key 与模型数量后按需勾选导入（操作步骤见 [备份与迁移](./maintenance#从其他平台迁移渠道)）。

## 常见问题

| 现象 | 检查要点 |
| --- | --- |
| 获取模型列表失败 | 检查 Base URL 是否误填了 `/v1/models` 后缀、Key 权限、代理设置，或上游是否禁用 `/models`（可关闭 **支持获取模型列表** 后手动录入） |
| 同步后模型突然消失 | 在 **模型组 → 同步记录** 查看是否为上游目录已移除该模型 |
| 测试返回 404 或协议格式错误 | 检查该模型的 **上游协议** 是否与供应商实际接口一致 |
| 列表中出现多个同名模型 | 它们属于同一渠道的不同 Key 或不同地址出口，各自独立计费与冷却 |
