# 管理模型组与路由

**模型组（Model Group）** 是客户端调用 Lens 时的唯一模型标识。客户端请求体中的 `model` 填写模型组名称；Lens 根据组配置将其调度到一个或多个“渠道 + Key + 上游模型”成员上。

## 自动归组与待分配模型

每次保存渠道、保存模型组、执行模型同步或应用启动时，Lens 都会运行一次 **模型归组（Reconcile）**：

1. 遍历所有已启用且可用的渠道模型，按 **直接调度组** 的名称与正则规则将其自动加入匹配组。
2. 未被任何组覆盖的模型：
   - 如果尚未存在同名组且无冲突，系统会自动创建一个同名的 **直接调度组**（默认 **故障切换** 策略）；
   - 如果名称与现有组存在交叉覆盖或此前被加入“自动建组排除名单”，则进入 **待分配模型（Unplaced Models）** 面板。
3. 在 **模型组** 右上角可打开 **同步记录** 查看每次归组的新增、建组、移除与待分配明细；在 **待分配** 面板中可批量将模型手动归入指定执行组或忽略移除。

![模型组列表中的成员、分发策略和操作入口](/images/model-groups.png)

> [!NOTE]
> 修改模型组规则只对**已保存在渠道中的模型**重新归组，不会替渠道向上游拉取新模型。新增模型请先在 [接入站点与模型](./sites) 中完成获取与保存。

## 两类模型组：直接调度 vs 别名

在模型组编辑器中，可以通过 **模型组类型** 实现两层路由解耦：

| 类型 | 角色 | 典型用途 |
| --- | --- | --- |
| **直接调度（执行组）** | 直接持有“渠道 + Key + 上游模型”成员，配置分发策略、匹配规则与回退组 | 管理同一模型的多家供应商，例如 `gpt-6.1-sol` 组下挂载供应商 A 与供应商 B |
| **别名（路由组）** | 不直接持有成员，而是指向一个 **直接调度组** | 为客户端提供稳定的业务名（如 `daily-chat`、`coding-fast`），后续切换底层模型只需改别名指向 |

**配置示例**（主备切换 + 稳定别名）：
1. 确保 `gpt-6.1-sol` 为 **直接调度** 类型，组内已挂载供应商 A（主）和供应商 B（备）。
2. 新建 `daily-chat` 模型组，类型选择 **别名**，目标指向 `gpt-6.1-sol`。
3. 客户端传入 `"model": "daily-chat"`。在 **请求日志** 中会分别记录请求模型 `daily-chat` 与实际执行组 `gpt-6.1-sol`。

> [!WARNING]
> 别名必须直接引用 **直接调度组**，不支持“别名引用别名”的多级链式跳转。

## 分发策略与故障切换细节

![模型组编辑：策略、匹配条件、渠道优先级和成员](/images/group-editor.png)

| 策略 | 调度方式 | 适用场景 |
| --- | --- | --- |
| **故障切换（Failover）** | 严格按组成员列表中配置的顺序依次尝试 | 主用高性价比/低延迟供应商，仅在限流或报错时切换备用供应商 |
| **平滑轮询（Round Robin）** | 在可用成员间使用平滑加权轮询（SWRR）；启用健康评分时，按最近成功率动态调整权重 | 多渠道或多 Key 负载均衡分摊流量 |

理解以下调度细节，可以避免“配置顺序与预期不符”的困惑：

- **故障后短期亲和（`failover_affinity_seconds`）**：在故障切换模式下，如果主成员 A 失败并由 B 成功接管，默认接下来 **30 秒** 内同一组请求会优先复用 B，避免每个请求都先撞一次刚失败的 A。
- **同 Key 多出口合并**：同一把 Key 如果对应同一站点的多个可用地址/协议，在平滑轮询中**只占一个轮询席位**（避免多填一个备用 URL 就权重翻倍）；其余出口仍保留在备选链中用于故障转移。两把不同的 Key 则是两个独立成员。
- **原生协议优先**：同一出口同时支持原生协议与跨协议转换时，路由器始终优先选择与客户端协议一致的原生出口。

## 匹配规则与成员来源

在 **直接调度** 组中，可以配置自动收集成员的范围：

- **组名包含匹配**：模型组名称默认作为 **不区分大小写的子串包含匹配**（例如组名 `gpt-6` 会同时匹配 `gpt-6.1-sol` 与 `gpt-6-luna`）。
- **正则与组合逻辑（`or` / `and`）**：
  - 选择 **或（OR）**：满足“组名包含”或“正则匹配”之一即加入；
  - 选择 **与（AND）**：必须同时满足“组名包含”和“正则匹配”才加入。
  - 正则默认可匹配名称片段；若要严格精确匹配单个模型，请使用 `^`、`$` 并对点号转义（如 `^gpt-6\.1-sol$`）。

| 目的 | 组名 | 组合方式 | 正则表达式 |
| --- | --- | --- | --- |
| 聚合某系列所有版本 | `claude` | 或 | （留空） |
| 严格锁定单一模型名 | `gpt-6.1-sol` | 与 | `^gpt-6\.1-sol$` |
| 自定义对外组名并自动收集指定上游 | `daily-chat` | 或 | `^gpt-6-luna$` |

### 成员来源与排除机制

组内成员分为三类来源，在重新归组时表现不同：

| 成员来源 | 行为说明 |
| --- | --- |
| **自动匹配 / 自动归组（`rule` / `placement`）** | 每次归组都会按当前规则重算；模型从渠道移除或不再匹配规则时自动移出 |
| **手动添加（`manual`）** | 即使模型名不符合组规则，也会持久保留在组内，仅当对应渠道/Key/模型被彻底删除时才移出 |
| **已排除（Excluded）** | 从组中手动移除的自动成员会进入“已排除”列表，后续自动归组会跳过它（同 Key 同模型共享排除状态）；可在编辑器内恢复 |

- **删除模型组**：未被其他组规则覆盖的成员会自动回到 **待分配列表**，且该模型会被记录到自动建组排除表中，防止下一次同步时立即重新自动建组。
- **合并模型组**：将源组的成员与别名引用转移至目标组并删除源组；操作前请确认旧名称没有客户端正在使用。

## 推理强度后缀（Reasoning Intent）

Lens 支持直接在客户端请求的 `model` 字段末尾通过括号指定推理强度或思考预算，网关会在路由时剥离后缀以匹配模型组，并自动将推理意图注入目标上游协议的对应字段：

- **标准强度档位**：`none`、`auto`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`
  - 示例：`daily-chat(high)`、`claude-opus-5-5(low)`、`gpt-6.1-sol(none)`
- **自定义思考预算（正整数 Token）**：例如 `claude-opus-5-5(16384)`

不同上游协议的自动映射如下：
- **OpenAI Chat** → `reasoning_effort`
- **OpenAI Responses** → `reasoning.effort`
- **Anthropic** → `thinking: { type: "enabled", budget_tokens: ... }`（`none` 转为 `disabled`；档位默认映射 1024–32768）
- **Gemini** → `generationConfig.thinkingConfig`

> [!WARNING]
> 括号后缀属于 Lens 路由契约的一部分；不受支持的括号内容会直接返回 `400 invalid_model`，不会透传给上游。

## 上下文过滤、多模态回退与组级覆盖

在组编辑器的高级配置中，还可设置：

- **默认上下文窗口**：当某个成员未单独设置上下文长度时作为回退依据。如果估算请求 Token 超过某成员已知窗口，路由器会跳过该成员；如果所有成员都不足，仍会保留候选池交由上游最终裁定，上游返回超长错误时再尝试下一成员。
- **多模态备用组（Multimodal Fallback）**：当请求体包含图片、文件或音频内容且当前执行组全部候选耗尽时，编排层会依次尝试配置的备用组；纯文本请求不会触发多模态回退。
- **组级请求头与参数覆盖**：与渠道级规则协同工作（参数覆盖按 **全局 → 渠道 → 请求模型组** 顺序叠加，后者覆盖前者，但禁止覆盖 `model` 字段）。
